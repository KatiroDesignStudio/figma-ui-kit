# Données de travail (`.uikit/`)

Aucun état ne survit entre deux appels `use_figma` : tout ce qui doit servir plus tard est écrit ici.
JSON, identifiants de nœuds Figma tels quels. Chaque fichier a un seul propriétaire, qui l'écrit ; les autres le lisent. Les agents n'écrivent que dans `.uikit/` (filtre du plugin) ; `uikit.md` n'est écrit que par la conversation principale : Kanshu, et Hairyo pour ses questions d'accessibilité (`pilotage.md`). Seule exception : `ids.json`, dont Seiso complète `lots` (ses propres lots) et `presentation`.

## Conventions
- Identifiant de lot : `P{phase}-{nn}` pour figma-ui-kit:build (`P3-02`) ; avec figma-ui-kit:templates, `K{nn}` pour une retouche du kit et `E{nn}` pour un écran.
- Dans un nom de fichier, le « : » d'un identifiant Figma devient « - » (`scan/2334-193.json`).
- Identifiant de constat : `C{nnn}`, jamais réutilisé, y compris dans les deltas. Une question de `uikit.md` cite les constats qu'elle couvre.
- Lien vers un nœud, pour l'utilisateur : `https://www.figma.com/design/{fileKey}/?node-id={id avec - à la place de :}`.
- Types de constats propres aux niveaux : `famille-atome`, `famille-molecule`, `famille-organisme` (famille proposée, avec `confiance` : `forte` ou `faible`) ; `molecules-manquantes` (signature répétée qui ne correspond à aucune famille du kit, quel que soit le niveau) ; `formes-multiples` (un même élément sous plusieurs formes, `catalogue.md`). Les autres types portent le nom du contrôle de `controles.md`.
- Un constat qui recompte un constat antérieur le cite dans `remplace` (`C024`) : seul le plus récent fait foi.
- Comptage des nœuds : méthode de `controles.md` (Unités de mesure).
- Un fichier se complète au fur et à mesure (page par page, lot par lot) : jamais tout en mémoire puis tout à la fin.
